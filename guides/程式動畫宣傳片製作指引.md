> 2026-11-03 建立。整理自兩個來源：本專案的〈Banana 18 Pro〉（`output/banana-18-pro/notes.md`）與一支外部參考片〈Overlay Studio 宣傳片〉（社群成員分享，素材在 `assets/參考/overlay-studio-宣傳片/`）。
> 2026-11-03 補充：從 `media-short-film` 的 `short-film` 技能移植生成前試映、觀眾入戲條件、自審清單、成片定案關卡與 CC0 音效庫的做法（第 5、6 節）。
> 用途：下次要做「全程用程式產生的 3D 宣傳／廣告片」時，照本指引開工。Blender 通用操作仍以 `blender` 技能為準，本檔只記這類片子的製作方法。

## 1. 這類片子是什麼

**全程式製作**：bpy 程序建模＋程式算出每一格的動畫 → Blender 算圖 → Python 合成字卡、轉場與調色 → numpy 合成配樂與音效 → FFmpeg 出片。不手調關鍵幀、不用剪輯軟體、不用生成式影片模型，所以每一格都能重現、能改。

| | 〈Banana 18 Pro〉（本專案） | 〈Overlay Studio 宣傳片〉（參考） |
|---|---|---|
| 長度／規格 | 60 秒、1920×1080、24 fps | 92 秒、看到的是 720p 30 fps（原始規格不明） |
| 主角 | 產品本體（一根香蕉），沒有表情 | 吉祥物「小克」：橘色方塊像素怪物，會飛、會說話 |
| 敘事 | 仿蘋果發表會：設計→配色→果肉→營養→能量→環保→英雄鏡頭→片尾 | 前半「軟體怎麼用」（6 個編號步驟），後半「這支片怎麼做的」（6 步後設揭密） |
| 鏡頭 | 14 個分鏡，靠合成階段的轉場銜接（flare、whip、flash、dissolve…） | **一鏡到底**，偵測不到任何硬切，換段落靠鏡頭飛越 |
| 背景 | 黑底、鏡面地板，背景光暈在合成時用 2D 畫 | 前半深色桌面＋散景光點；後半換成 macOS 風漸層桌布＋Dock |
| 畫面上的字 | 全英文大標／副標、營養數字、片尾卡 | 中文編號標題卡、聊天氣泡、左上角 1/6～6/6 進度條、底部常駐章節列 |
| 聲音 | numpy 合成的 D 小調 120 BPM 配樂，每個轉場、字卡、燈亮都有對應音效 | `audio.py` 用程式合成配樂（從波形看沒有旁白），開頭有打字／UI 提示音 |
| 自述數字 | 約 3,300 行程式、約 1,500 格 | 5,544 行代碼、2,756 格、0 個手調關鍵幀 |

**值得學的手法**

1. **只有一個主角、一個舞台**：所有 UI 畫面都當貼圖貼在平板螢幕上，3D 只負責「主角＋螢幕＋鏡頭」。場景簡單，運鏡就能做得很放肆。
2. **UI 是 2D 先畫好的圖**：聊天氣泡、軟體畫面、程式碼視窗、統計卡都是平面圖，貼在 3D 平面上再算圖。文字清晰度靠 2D 端控制，不在 Blender 裡排字。
3. **淺景深＋動態模糊**：焦點外的 UI 全糊掉，既有質感，又遮掉貼圖解析度不足與 UI 細節的瑕疵。
4. **固定的導覽元素**：左上角段落進度條（1/6～6/6）＋底部三段章節列（隨播放前進），觀眾隨時知道自己看到哪裡。
5. **主角串場**：小克在每個段落都有事做（飛到重點、跳進 App 圖示、坐在統計卡旁），取代傳統轉場。
6. **後設段落當賣點**：後半直接揭密「全是代碼」並給出數字，最後以「留言領提示詞」導流。社群上的互動多半來自這一段。

## 3. 從〈Banana 18 Pro〉學到的

完整內容見 `output/banana-18-pro/notes.md`；這裡只留可以搬到下一支片的做法。

### 架構

- **時間軸只有一份**（`common/timeline.py`）：FPS、BPM、分鏡起訖格、轉場、字卡、數字都寫在這裡，Blender、合成、配樂三邊都 import 它。改節奏或分鏡長度只改一個檔，三邊一起跟著動。
- **格數對齊節拍**：120 BPM × 24 fps → 一拍 12 格、一小節 48 格。分鏡長度、重拍、燈亮都落在整拍上，畫面和音樂自然對得上。
- **動畫寫成「格數 → 數值」的函式，再逐格烘成線性關鍵格**（`shots.py` 的 `bake()`、`bake_camera()`）：攝影機、燈光、形變都一樣，動態模糊因此正確，也不用手調關鍵幀。緩動函式（`ease_io`、`ease_out_expo`…）自己寫在檔案開頭。
- **每個分鏡多算 `HANDLE` 格**，給合成階段的溶接用。
- **3D 只算主體，算圖用透明背景**；背景光暈、字卡、轉場、暗角、調色、顆粒都在 `composite.py` 用 numpy／Pillow 做。改字或改轉場不必重算 3D。
- **共用幾何寫成 Blender 與 PIL 都能讀的模組**（`common/logo.py`）：3D 標誌和 2D 片尾卡用同一份形狀。
- **先做定裝照**（`blender/charsheet.py`：四視角、各配色、各狀態），使用者確認造型後才進分鏡。

### 流程與指令

```bash
S=<本機暫存資料夾，不要放雲端硬碟>
# 預覽：1/4 解析度、8 samples、每 6 格一張、關動態模糊（14 鏡約 1 分鐘）
bash tools/render_shots.sh $S/prev $S/tex 0.25 8 6
# 正式：全解析度、64 samples、每格都算
bash tools/render_shots.sh $S/final $S/tex 1 64 1
uv run --with numpy python audio/synth.py $S/score.wav
uv run --with numpy --with pillow python comp/composite.py --frames $S/final --audio $S/score.wav --out <成品.mp4>
```

- 分鏡逐格 PNG 與配樂 wav 放**本機暫存**，不放雲端硬碟（上千張圖會拖垮同步）；只有成片與定裝照進作品資料夾。
- `composite.py --png-dir` 可以只輸出幾格靜態圖檢查字卡與調色。
- 出片同時產生母帶（CRF 14、AAC 256k）與分享版（CRF 21），並加 `-map_metadata -1` 清掉 metadata。

### 踩過的坑

- 這台電腦的應用程式控制會擋 scipy 的 DLL → 配樂只用 numpy，濾波與殘響自己用 FFT 寫。
- 形狀鍵＋曲面細分在 GPU 上會爆出破面 → 改用 `frame_change_pre` handler 每格改寫頂點。
- Solidify 的 `use_even_offset` 在捲曲處會爆面 → 關掉，改 `use_quality_normals`。
- 鏡頭後方的發光背景板會露邊 → 改透明背景，光暈在合成階段畫。
- EEVEE 面光預設會入鏡 → `visible_camera = False`。
- **透明背景＋不透明地板＝硬地平線**：柔邊物體在線上下各混到不同底色，看起來斷成兩截 → 地板材質依距離漸變成透明（`floor(fade=(50, 250))`）。
- 聲音 agent 聽不到 → 配樂與音效一定要使用者試聽確認。

## 4. 兩條路線怎麼選

| | A. 多分鏡＋合成轉場（Banana 式） | B. 一鏡到底＋吉祥物（Overlay 式） |
|---|---|---|
| 適合 | 產品發表、氣氛型廣告、很多不同場景 | 軟體或流程介紹、教學、「怎麼做的」揭密 |
| 好處 | 每鏡獨立，改一鏡只重算一鏡；轉場在 2D 端好調 | 連貫、有記憶點；主角有個性，好做系列 |
| 難處 | 轉場太多會像幻燈片 | 一個長鏡頭要切成多段算圖，段落接縫處的攝影機與主角位置必須連續；改中間一段可能牽動前後 |
| 3D 內容 | 產品模型、材質、燈光要精緻 | 主角簡單（方塊即可），重點在運鏡與 UI 貼圖 |
| 2D 內容 | 字卡、光暈、轉場 | 大量 UI 畫面、聊天氣泡、標題卡、進度條，都要先用 Pillow 畫成貼圖 |

**B 路線的做法**（推論，尚未在本專案實測）：

- 時間軸仍用一份 `timeline.py`，只是「分鏡」改成「段落」，每段寫明攝影機要從哪到哪、主角要做什麼、螢幕要顯示哪張 UI。
- 攝影機路徑寫成整支片一條連續函式 `cam(frame)`，算圖時依段落切成多個區間分別算（方便重算單段），合成時直接串接、不加轉場。
- 螢幕上的 UI 用 Pillow 逐格或逐段產生成圖片序列，Blender 的螢幕材質讀圖片序列；聊天打字效果就是逐格多一個字。
- 文字（標題卡、進度條、章節列）能放在 2D 合成層就不要放進 3D；只有「貼在螢幕上、會跟著透視變形」的才進 3D 貼圖。
- 背景切換（深色→彩虹桌布）用鏡頭飛越遮擋的瞬間換，或在合成層做大面積擦除。

## 5. 製作流程（照順序做）

### 0. 開工前先和使用者確認（一次問完）

- 主題與要推的東西（產品、軟體、概念）；片子要讓觀眾記住哪一句話。
- 走 A 還是 B 路線；有沒有「這支片怎麼做的」後設段落。
- 長度、比例（16:9／9:16／兩者都要）、語言（畫面字中文或英文）。
- 主角：產品本體還是吉祥物；吉祥物要不要說話、有沒有名字。
- 配色與調性（例：黑底＋金色／深色底＋糖果色點綴）。
- 配樂風格與速度（BPM 決定一拍幾格）。

只問會實質改變結果的缺漏，一次問完；其餘採合理假設。決定寫進作品的 `report.md`〈使用者的決定〉，之後不再重問；沒經使用者確認的逐條寫進〈假設〉，不要混進〈使用者的決定〉。

### 1. 分鏡與時間軸

先用表格和使用者對過一次分鏡，再寫 `timeline.py`：FPS、BPM、總格數、段落起訖、轉場、字卡、數字。

分鏡表要過〈觀眾入戲條件〉（移植自 media-short-film 的 `audience-entry.md`）：

- **前 3 秒靜音測試**：不看字、不聽聲音，只看開頭兩秒的畫面，說得出「誰、在哪、哪裡不對勁」才合格。
- **衝突要快、答案要慢**：開頭先給目標觀眾真的遇過的痛點（讓他覺得「這就是我」），解法到後面才揭曉。
- **熟悉裡有一個意外**：熟悉的場景讓人看得懂，意外讓人留下來；相鄰段落的情緒要不同。
- **留一個沒回答的問題**：每段結尾讓觀眾心裡冒出一個問句，帶到下一段。

### 1.5 生成前試映

`timeline.py` 寫好、還沒建 3D 之前，用 Pillow＋FFmpeg 從時間軸產生一支靜音的讀本試映（`work/previews/讀本試映.mp4`，1280×720）：每段停留＝實際長度，畫面放段落名稱、標題卡與氣泡文字，下方標時間碼。回報估計總長與目標的差距、最長的三段、文字太多讀不完的段落（中文約每秒 5–6 字）。使用者看完說「通過」才往下做。超長就刪字或併段，不要靠加快節奏。

### 2. 主角與定裝照

建主角模型與材質，輸出定裝照（多視角、各配色、各狀態），使用者確認後才往下做。會跨作品重複出現的角色放 `assets/角色/<角色>/`：`README.md`（鎖定的外觀描述、尺寸、配色色碼）、定裝照、可重用的 bpy 建模模組；作品從這裡 import，不在各作品各做一份，造型才不會漂。

### 3. 場景與 2D 素材

舞台（地板、桌面、平板）、燈光、背景；B 路線先把所有 UI 畫面用 Pillow 畫好。

### 4. 動畫

每段的攝影機、主角、燈光都寫成格數函式，逐格烘焙。主角的「個性動作」（彈跳、擠壓伸展、眨眼）做成可重用的函式。

### 5. 低成本預覽

1/4 解析度、低 samples、跳格、關動態模糊，整支跑一次，輸出接觸表給使用者看構圖與節奏。正式算圖預估超過 5 分鐘時先告知使用者。

### 6. 配樂與音效

`synth.py` 讀同一份時間軸，段落換場、字卡出現、主角動作都配音效。產出後請使用者試聽。

UI 提示音、打字音可用 numpy 合成；人群掌聲、歡呼、翻頁這類真實聲音合成會很假，改用 media-short-film 的 `sfx/` CC0 音效庫（Freesound CC0，可商用、免標示；分類與編號見它的 `sfx/README.md`、`manifest.json`）。只把用到的檔複製進作品的 `work/sfx/`，Freesound 編號與網址寫進 `report.md`。要新增時只收 CC0。

### 7. 正式算圖

逐格 PNG 放本機暫存。場景改過就先清掉舊的格圖快取，避免混入舊畫面。

### 8. 合成與出片

`composite.py` 疊背景、字卡、轉場、調色、顆粒，ffmpeg 合音軌出片；母帶＋分享版，清 metadata。成片先輸出在 `work/` 下（例：`work/cut/成片_v<N>.mp4`），還不放作品根目錄。

### 9. 自審

交給使用者看之前，agent 先照第 6 節〈自審清單〉審完、修完。回報時附自審報告：用**成片時間碼**對應問題、修了什麼、沒量的項目照實寫「沒量」。

### 10. 定案與交付

自審報告交出後問使用者「可以成片嗎？」，**說可以才做**：

1. 把成片移到作品根目錄、改名 `<作品>.mp4`；根目錄已有之前定案的版本，先照 AGENTS.md 的規則把舊版整份搬進 `舊版/vNN/`，不覆蓋。
2. 依 AGENTS.md 的作品資料夾規則放好 `scene.blend`、封面、`report.md`、`build_scene.py`，其餘腳本進 `work/`。
3. 寫 `發布資訊.md`，揭露「程式由 AI 協助撰寫」，有用 CC0 音效時列出來源。

還在改就不做，定案後又要改就再問一次。使用者的回饋原文記進 `report.md`；「技術檢查通過」和「使用者驗收通過」分開記錄，不擅自把前者寫成後者。退件理由收斂成一條祈使句，跨作品適用的寫進本指引或 AGENTS.md，不要只寫 agent 記憶（每台電腦各一份、不會同步）。

## 6. 自審清單

移植自 media-short-film 的 `docs/04_自審清單.md`，改成 3D 程式動畫會出的問題。

**畫面**（逐段抽格拼成總覽圖，逐張人工看；每支片至少看一張 100% 原尺寸全幀，只看縮圖會漏）

- [ ] 破面、穿模、法線翻轉、陰影痤瘡
- [ ] 地平線硬邊、背景板露邊、面光入鏡
- [ ] 段落接縫：攝影機與主角位置、朝向、燈光連續，沒有跳一格
- [ ] UI 貼圖與字卡：錯字、亂碼、字被裁掉、溢出框外、焦外糊到讀不出該讀的字
- [ ] 角色造型與 `assets/角色/<角色>/README.md` 一致（配色、比例、配件）
- [ ] 沒有混入舊格圖快取（場景改過就清快取）

**技術**（用程式量）

- [ ] 總格數、fps、解析度與時間軸一致；全片可完整解碼
- [ ] 沒有黑畫面、沒有超過 0.8 秒的意外定格
- [ ] 整體響度約 −15 LUFS、真峰值 < −1.5 dBFS
- [ ] 音效對到畫面事件（差不到一格）、配樂小節對到段落換場

**原則**

- 不合格就重做該段，不靠剪掉或蓋字卡躲。
- 給使用者看並排影片或抽格，數字只當備註；沒被點名的段落不要動。

## 7. 新作品的程式配置建議

〈Banana 18 Pro〉用的是 `common/ blender/ audio/ comp/ tools/` 結構（搬入時保留，是例外）。新作品照 AGENTS.md 的作品資料夾規則：

```text
output/<作品>/
├── <作品>.mp4             成片（分享版）；母帶可加後綴
├── scene.blend            主要場景（或最具代表性的段落）
├── cover*.png
├── report.md              使用者的決定、假設、分鏡表、重現指令、自審紀錄、踩坑
├── 發布資訊.md
├── build_scene.py         主腳本：建場景（角色從 assets/角色/<角色>/ import）
└── work/
    ├── timeline.py        全片唯一時間軸
    ├── table_read.py      從時間軸產生讀本試映
    ├── shots.py           各段攝影機與動畫、算圖入口
    ├── ui.py              （B 路線）Pillow 畫 UI 貼圖
    ├── synth.py           配樂與音效（numpy）
    ├── composite.py       合成與出片
    ├── render.sh          批次算圖
    ├── sfx/               用到的 CC0 音效（從 media-short-film 的 sfx/ 複製）
    ├── cut/               定案前的成片 成片_v<N>.mp4
    ├── previews/          讀本試映、接觸表與驗收抽格
    └── log/
```

逐格 PNG 與 wav 不放這裡，放本機暫存資料夾，在 `report.md` 寫明怎麼重產。
